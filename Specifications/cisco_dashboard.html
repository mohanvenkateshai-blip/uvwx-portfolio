The Four Defense Pillars

Interact with the tabs below to explore the specific technical requirements for each layer of the security framework. These pillars represent the core configuration standards required to protect both the application and the underlying operating system.

01. Network Stealth

The "Invisible" Layer: Ensuring the hosting machine cannot be discovered or accessed directly via the public internet.

Requirement
Zero-Exposure / No Port Forwarding
Actionable Standard
Deploy an egress-only tunnel (e.g., Cloudflare Tunnel, Ngrok). Configure the router to maintain 0 inbound open ports. Mask the public IP entirely behind the CDN edge.
💡 CISO Rationale
Attackers scan public IP ranges constantly. By using a tunnel, your machine establishes an outbound connection to the proxy, bypassing the need for an open firewall port and stopping automated botnet discovery.

02. Host Hardening

The "Bunker" Layer: Minimizing the attack surface of the underlying operating system per NIST 800-123.

Requirements
Service Minimization, Privilege Isolation, Disk Encryption
Actionable Standard
  • Disable high-risk legacy services: SMB, RDP, Print Spooler.
  • Run web services (Nginx/Apache) under a dedicated, non-admin user (e.g., www-data).
  • Enable AES-256 Full Disk Encryption (BitLocker, FileVault, LUKS).
💡 CISO Rationale
If the web application is compromised, Privilege Isolation ensures the attacker cannot escalate to root control. Disk encryption protects data if the physical hardware is stolen.

03. Transit Protection

The "Vault" Layer: Enforcing modern encryption standards to protect data in motion against interception.

Requirement
Strict TLS 1.3 Enforcement (RFC 8446)
Actionable Standard
Configure the web server to explicitly disable SSLv3, TLS 1.0, TLS 1.1, and TLS 1.2. Only allow TLS 1.3 cipher suites.
💡 CISO Rationale
Legacy protocols contain mathematical vulnerabilities allowing downgrade attacks (like POODLE). Enforcing TLS 1.3 ensures the cryptographic handshake is secure from modern interception techniques.

04. App Defense

The "Shield" Layer: Implementing server-level mitigations against common OWASP web vulnerabilities.

Requirement
Mandatory OWASP Security Headers
Actionable Standard
Strict-Transport-Security: max-age=63072000; preload
Content-Security-Policy: default-src 'self'
X-Frame-Options: DENY
X-Content-Type-Options: nosniff
💡 CISO Rationale
Headers are the first line of defense. HSTS forces HTTPS, CSP neutralizes Cross-Site Scripting (XSS), and X-Frame-Options prevents attackers from hijacking clicks via invisible iframes.
